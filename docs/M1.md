# EasyADB M1 — 多设备管理

M1 分支基于 feat/adb-connect-preview（MVP 尚未合并 main）。仅实现设备连接管理；不包含实时投屏、触控、自动化脚本或 Agent。

## 已实现

- 可保存多台手机的名称、分组、**组网 IP**（手动填写 IPv4）、无线 ADB 连接端口与自动重连开关；相同组网 IP + 端口不能重复保存。
- 设备列表按分组展示，分组可折叠，未设置分组的设备归入「未分组」；分组显示当前已连接数量。添加/编辑设备使用弹窗，分组输入可选择已有名称或录入新名称；支持删除、按设备 ID 连接、按设备 ID 截图、手动刷新设备或全体状态。
- **分组内网映射**：在「＋ 添加分组」或现有分组「设置」弹窗配置可选 `192.168.10.*`；设备组网 IP `10.10.30.206` 派生出内网 IP `192.168.10.206`。不另外生成设备记录。优先连接内网 IP，失败则尝试组网 IP；未设置分组前缀时只使用组网 IP。设备卡片显示两种 IP 及实际连接地址，截图严格使用当前实际 ADB serial，避免串台。
- 启动时自动创建 `group_configs` 并迁移原有非空分组名称，**不覆盖已有设备记录或授权密钥**；编辑分组名称会连同成员记录一并更新。相同 IP+端口若会同时指向两台不同设备，API 返回 409，避免误操作其他设备。
- 独立后台监控线程每 20 秒依次检查设备；仅对打开自动重连的离线设备发起 adb connect，避免不同网页各自创建轮询。
- 连接成功后读取型号和 Android 版本；重启服务后实时状态重新检查，不持久化虚假的在线状态。
- 原有 /api/connect、/api/status、/api/screenshot 保留兼容，M1 页面不再依赖全局当前设备。

## FNOS 部署

1. **首次从旧 MVP 脚本升级**：在现有 EasyADB 目录执行 `git fetch origin`，然后 `git switch --track origin/feat/m1-multi-device`（若本地 M1 分支已存在，则 `git switch feat/m1-multi-device`），再执行 `git pull --ff-only origin feat/m1-multi-device`。旧脚本无法自行获得尚未下载的自动更新功能。
2. 此后保留原来的 `.env`、`proxy-net` 及 Mihomo 设置，每次只需运行 `sudo sh scripts/build-with-mihomo.sh`。它会自动通过原登录用户执行 `git fetch origin`、切换到 M1 分支并 `pull --ff-only`，重新加载最新脚本后构建及覆盖部署。遇到本地未提交或未跟踪文件、非快进更新时会停止，不执行破坏性覆盖。
3. 浏览器访问 FNOS 既有 EASYADB_BIND_IP:EASYADB_PORT（例如 8765），输入 EASYADB_TOKEN 后加载设备。
4. 点击「＋ 添加分组」新建分组，或在已有分组的「设置」弹窗填写 **内网 IP 前缀**（如 `192.168.10.*`，可留空）；点击「＋ 添加设备」填写**组网 IP**（如 `10.10.30.206`）及连接端口、选择分组。首次授权可使用设备弹窗内的配对折叠项（配对弹窗端口与连接端口不同）。修改分组前缀会自动重新计算成员内网 IP，并让缓存连接状态重新检查。

新增数据持久化挂载：FNOS ./data/storage → 容器 /app/data，数据库为 devices.sqlite3；原 ./data/adb → /root/.android 的授权密钥挂载不变。请备份整个 ./data，勿提交 .env 或 ADB 密钥。

## API（均需 X-EasyADB-Token）

| 请求 | 说明 |
|---|---|
| GET /api/devices | 设备列表、派生内网 IP、当前连接地址及状态 |
| GET /api/groups | 分组名称与内网 IP 前缀 |
| POST /api/groups | 添加分组（名称、可选 ip_prefix） |
| PUT /api/groups/{name} | 修改分组名称与前缀，原有成员同步更新 |
| POST /api/devices | 新增设备 |
| PUT /api/devices/{id} | 编辑资料，保留设备逻辑 ID |
| DELETE /api/devices/{id} | 删除列表记录，不撤销系统配对 |
| POST /api/devices/refresh | 检查全部设备 |
| POST /api/devices/{id}/refresh | 检查指定设备 |
| POST /api/devices/{id}/connect | 手动连接 |
| GET /api/devices/{id}/screenshot | 获取该设备当前 PNG 截图 |
| POST /api/pair | 首次无线 ADB 配对 |

POST/PUT 设备字段：name、group_name、ip（即组网 IP）、port、auto_reconnect。分组字段：name、ip_prefix（空值表示不生成内网 IP）；设备响应的 mesh_ip 等于旧字段 ip，lan_ip 是派生地址，active_route 为 lan 或 mesh，active_serial 是当前真实连接的 IP:port。单线程监控可能在设备很多或多个设备不可达时出现顺序检测延迟；Uvicorn 保持一个 worker 以免重复心跳。

## 本地测试

安装 server/requirements.txt、pytest 和 httpx，设置 EASYADB_TOKEN=local-test-token-123 后运行 python -m pytest -q；可选 EASYADB_DB 环境变量更改 SQLite 路径。本机必须安装 adb 才能与真机联调。

## FNOS 真机验收

- 两台手机分别保存、连接、截图，不得串台。
- 修改其中一台端口、重启容器后仍保留设备档案。
- 离线设备正确显示异常；开启自动重连后网络恢复可再次连接。
- 分组设置 `192.168.10.*` 后设备 `10.10.30.206` 出现内网 IP `192.168.10.206`；内网可达时优先使用内网，内网失败且组网可达时回退组网，截图对应实际连上的地址；取消前缀后自动清除内网候选地址。
- Android 系统无线调试被关闭、授权失效或动态端口变化时，仍需用户重新开启/授权或编辑端口；自动重连不会绕过 Android 系统限制。两条候选地址目前共享设备登记的同一个 ADB 连接端口。
