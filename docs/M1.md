# EasyADB M1 — 多设备管理

M1 分支基于 feat/adb-connect-preview（MVP 尚未合并 main）。仅实现设备连接管理；不包含实时投屏、触控、自动化脚本或 Agent。

## 已实现

- 可保存多台手机的名称、分组、IPv4、无线 ADB 连接端口与自动重连开关；相同 IP + 端口不能重复保存。
- 支持列表、编辑、删除、按设备 ID 连接、按设备 ID 截图、手动刷新设备或全体状态。
- 独立后台监控线程每 20 秒依次检查设备；仅对打开自动重连的离线设备发起 adb connect，避免不同网页各自创建轮询。
- 连接成功后读取型号和 Android 版本；重启服务后实时状态重新检查，不持久化虚假的在线状态。
- 原有 /api/connect、/api/status、/api/screenshot 保留兼容，M1 页面不再依赖全局当前设备。

## FNOS 部署

1. 在现有 EasyADB 目录执行 git fetch origin，再切换到 feat/m1-multi-device（未创建本地分支用 git switch --track origin/feat/m1-multi-device）。
2. 保留原来的 .env、proxy-net 及 Mihomo 设置，运行 sudo sh scripts/build-with-mihomo.sh。
3. 浏览器访问 FNOS 既有 EASYADB_BIND_IP:EASYADB_PORT（例如 8765），输入 EASYADB_TOKEN 后加载设备。
4. 添加手机的无线调试主页 IP 和**连接端口**；首次授权先使用配对入口（配对弹窗端口与连接端口不同）。

新增数据持久化挂载：FNOS ./data/storage → 容器 /app/data，数据库为 devices.sqlite3；原 ./data/adb → /root/.android 的授权密钥挂载不变。请备份整个 ./data，勿提交 .env 或 ADB 密钥。

## API（均需 X-EasyADB-Token）

| 请求 | 说明 |
|---|---|
| GET /api/devices | 设备列表及缓存的实时状态 |
| POST /api/devices | 新增设备 |
| PUT /api/devices/{id} | 编辑资料，保留设备逻辑 ID |
| DELETE /api/devices/{id} | 删除列表记录，不撤销系统配对 |
| POST /api/devices/refresh | 检查全部设备 |
| POST /api/devices/{id}/refresh | 检查指定设备 |
| POST /api/devices/{id}/connect | 手动连接 |
| GET /api/devices/{id}/screenshot | 获取该设备当前 PNG 截图 |
| POST /api/pair | 首次无线 ADB 配对 |

POST/PUT 设备字段：name、group_name、ip、port、auto_reconnect。单线程监控可能在设备很多或多个设备不可达时出现顺序检测延迟；Uvicorn 保持一个 worker 以免重复心跳。

## 本地测试

安装 server/requirements.txt、pytest 和 httpx，设置 EASYADB_TOKEN=local-test-token-123 后运行 python -m pytest -q；可选 EASYADB_DB 环境变量更改 SQLite 路径。本机必须安装 adb 才能与真机联调。

## FNOS 真机验收

- 两台手机分别保存、连接、截图，不得串台。
- 修改其中一台端口、重启容器后仍保留设备档案。
- 离线设备正确显示异常；开启自动重连后网络恢复可再次连接。
- Android 系统无线调试被关闭、授权失效或动态端口变化时，仍需用户重新开启/授权或编辑端口；自动重连不会绕过 Android 系统限制。
