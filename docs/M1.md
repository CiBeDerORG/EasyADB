# EasyADB M1 — 多设备管理与手动连接地址选择

M1 基于 `feat/adb-connect-preview`；不包含实时投屏、触控、自动化脚本或 Agent。**不存在后台定时 ADB 探测、定时连接、自动重连，也不存在连接失败后自动换 IP 的机制。**

## 功能

- 保存多台设备的名称、分组、组网 IP（`ip` / `mesh_ip`）、ADB 连接端口；列表按组折叠、显示当前连接数量，未分组设备独立展示。设备添加与编辑统一采用弹窗。
- 分组的内网 IP 前缀为可选配置，例如 `192.168.10.*`，组网 IP `10.10.30.206` 对应派生内网 IP `192.168.10.206`。内网 IP 与组网 IP 是同一设备的两个候选地址，不会重复建设备记录。
- **连接地址由用户手动切换**：设备卡片中两种 IP 后分别有「⇄ 切换」；选中的地址高亮，点击后通过 `PUT /api/devices/{id}/route` 将 `selected_route=mesh/lan` 写入 SQLite。切换不会执行任何 ADB 命令，仅清空旧连接状态和旧截图。需要用户明确点击「连接」，才会对所选地址执行 `adb connect`。
- 连接、手动单设备或全部状态检查、截图均只针对**当前保存的连接地址**（`selected_serial`）；某条路线失败时绝不尝试另一条，必须由用户亲自切换。手动状态检查仅执行 `get-state`，不会连接；页面不包含 20 秒定时检查。
- **失败后首次连接入口**：只有用户明确点击「连接」失败，当前选择的 IP 旁才显示「首次连接」。点击打开独立无线 ADB 配对弹窗，IP 根据已保存的 `selected_serial` 自动带入且只读，配对端口和六位配对码从手机无线调试的配对窗口手动填写。服务端按设备 ID 读取并校验当前选中地址，防止使用其他标签页变更前的旧地址。配对成功后提示手动再次点击「连接」，绝不自动重试/切换 IP；切换连接地址或连接成功会隐藏入口。单纯「检查全部状态」不会显示首次连接入口。原添加设备弹窗中的配对方式保持可用。
- 成功连接后读取型号与 Android 版本。截图只使用当前选择且已连接的实际 `active_serial`，不会沿用切换前的另一地址。容器重启后保留 `selected_route`，状态为「待手动连接」，不会自动连接或沿用陈旧在线状态。
- 分组名称变更会原子更新成员；前缀变更会重新派生选中的内网 IP 并清空旧连接状态。若内网映射被取消、删除分组或成员移至无内网前缀的分组，原先选择内网的设备会在 SQLite 中退回选择组网 IP，**但不会自动连接**。删除分组保留设备 ID、组网 IP、端口和 ADB 授权，成员移动到未分组。
- 若两个不同设备的候选 IP 与端口产生冲突，相关写操作事务回滚并返回 409，避免错误定位其他设备。

## 既有数据库兼容

`./data/storage/devices.sqlite3` 不需要删除；启动时新增 `devices.selected_route` 字段，原有记录统一默认 `mesh`（组网 IP）。旧 `auto_reconnect` 列为了无损兼容仍保留在数据库内，但**完全不读取、不返回、不执行**，原本勾选过自动重连的设备也不会被后台访问。原 `./data/adb` 和 `.env` 原样保留。

## FNOS 部署

已经使用 M1 新版部署脚本后，在项目目录重复执行：

```sh
cd /vol3/1000/software/EasyADB
sudo sh scripts/build-with-mihomo.sh
```

不带参数时，它会用原登录用户身份进行 `git fetch`、切换至 `feat/m1-multi-device`、`pull --ff-only`，然后重新载入构建脚本，经现有 Mihomo/proxy-net 进行 Buildx 构建与 Compose 覆盖部署。未提交文件或分支分叉时安全停止，不会覆盖 `.env`、`data/`。如果还使用最早的 MVP 脚本，需要先手工 fetch 和 switch 到 M1 以取得新版脚本。

**无代理模式（需显式指定）**：OpenWrt 等已经统一管理 Docker 出站的环境可执行：

```sh
sudo sh scripts/build-with-mihomo.sh --no-proxy
```

它依旧先自动更新 M1，并在更新后保留 `--no-proxy` 参数，但不读取 `EASYADB_BUILD_PROXY`、不依赖 Mihomo、`proxy-net` 或专用 BuildKit 构建器；直接使用 Docker 默认构建/网络，采用独立 `compose.no-proxy.yaml` 启动。该独立 Compose 文件仍与默认模式共用同一项目名称、镜像、端口和 `./data/adb`、`./data/storage` 挂载。需要切回原代理模式只要去掉参数，不会删除数据。无代理并不意味着强行绕过 OpenWrt 的透明代理或宿主机自有网络策略；前提是 Docker 构建能正常访问 Docker Hub、apt、Google Android 平台工具和 PyPI。

如果 FNOS 上已有的是**尚不识别 `--no-proxy` 的旧脚本**，第一次切换前先以 Git 登录用户执行 `git fetch origin && git pull --ff-only origin feat/m1-multi-device`，获得更新版脚本后再运行带参数命令；不要直接让旧脚本处理此新参数。

## API（均需 X-EasyADB-Token）

| 请求 | 用途 |
|---|---|
| GET/POST `/api/groups` | 分组列表、创建 |
| PUT/DELETE `/api/groups/{name}` | 修改、删除分组（成员移至未分组） |
| GET/POST `/api/devices` | 列表、添加设备 |
| PUT/DELETE `/api/devices/{id}` | 编辑、删除设备 |
| PUT `/api/devices/{id}/route` | 请求 `{"route":"mesh"}` 或 `{"route":"lan"}`；只持久化选中的连接地址，不触发 ADB |
| POST `/api/devices/{id}/connect` | 只对已选 IP 手动执行连接，无回退 |
| POST `/api/devices/{id}/pair` | 用户手动首次配对，提交 `port`（配对端口）、`code`、`selected_serial`；只使用当前保存的选中 IP，不自动连接 |
| POST `/api/devices/{id}/refresh` | 仅检查该设备当前选择的地址 |
| POST `/api/devices/refresh` | 一次性检查所有设备的已选择地址，不执行 adb connect |
| GET `/api/devices/{id}/screenshot` | 截取当前选择、已连接地址的 PNG |
| POST `/api/pair` | 首次无线 ADB 配对 |

添加、编辑设备请求字段：`name`、`group_name`、`ip`（组网 IP）、`port`。设备响应还含 `mesh_ip`、`lan_ip`、`selected_route`、`selected_serial`；`active_route`、`active_serial` 只有成功连接后才有效。若设备不具备内网 IP，切换至 `lan` 返回 409。

## 测试与真机验收

安装 `server/requirements.txt`、`pytest`、`httpx` 后运行 `EASYADB_TOKEN=local-test-token-123 python -m pytest -q`。CI 同时检查 Python、Shell 和页面 JavaScript 语法。

FNOS 重点验收：启动及重启后无人操作时不会执行定时 ADB 命令；点击切换后页面高亮与数据库保持一致、不立即连接；手动连接只走选中 IP；连接失败不尝试另一 IP，并在选中地址后显示首次连接按钮；弹窗读取选中 IP、要求另填配对端口/六位码；配对成功后不自动连接；连接成功或切换 IP 后按钮消失；单纯状态检查不触发该按钮；切换后旧截图失效；分组删除或取消内网前缀后默认组网 IP；原设备和授权数据继续保留。

两种地址目前沿用同一台设备登记的 ADB 连接端口。Android 系统关闭无线调试或端口改变后，仍需要用户手动开启或修改，EasyADB 不会绕过系统限制。
