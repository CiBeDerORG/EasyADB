# M2-EXP-001 · 电脑模式实验室（A/B 组）

实验分支：`feat/display-mode-lab`，以 `feat/m2-web-control` 为基线。

本功能仅验证显示源，**不承诺激活华为原生电脑模式**。不使用 Root，不扫描其它连接地址，不启动系统自带以外的未知 Activity，不修改现有 MSE 默认投屏链路。

## 入口和动作

设备管理 → 目标设备 →「电脑模式实验」。请先手动连接该设备，选择正确内网/组网/临时 IP:端口，并确保 ADB 授权正常。

- 环境检测：系统 Android 版本、API 级别、scrcpy-server 固定版本及 `dumpsys display`。
- A1：该设备没有已占用的直播会话时，经内置 scrcpy-server 启动 `new_display=1920x1080/240`；沿用原 MSE 实时画面。
- A2：同样先启动虚拟显示器，**只在本次显式启动时**查询新出现的 Display ID，并尝试 `adb shell am start --display <新ID> -a android.settings.SETTINGS`。即使启动设置失败，仍可观察视频实验结果。
- B1：保存之前的 `settings get global overlay_display_devices`，原子落盘至数据库路径旁边的 `*.display-lab.json`，然后才执行 `settings put global overlay_display_devices 1920x1080/240`。如果原本就是此设置，则不接管，也不会在恢复时误删。
- B2：读取 `dumpsys display` 的解析结果和截断原文，显示当前 Display ID（不假定第二屏是 ID 1）。
- B3：选择 B2 发现的非零 ID，以内置 scrcpy-server 的 `display_id=<ID>` 开启原 MSE 实时预览；服务端会再次验证该 ID 在当前已连接设备上存在。
- 停止此设备实验画面：只结束对应设备的现有 M2 会话；等待彻底清理后才能再次创建本设备虚拟屏幕或恢复 B 组设置。
- 恢复：仅连接到 B1 备份时相同的设备串号，且当前设置仍为 B1 写入值或原始值时才执行；恢复后重新读取验证。失败时保留待恢复记录。
- 导出：提供当前可见的扫描摘录和本进程操作日志 JSON，不包括访问密钥、截图或实时视频。

## Mate 30 建议操作顺序

1. 先执行环境检测，记录 Display ID。
2. 点击 A1，检查网页实时画面是否出现桌面、普通 Android 界面或黑屏；点击原有「停止此路」或实验室「停止此设备实验画面」。
3. 完全停止后尝试 A2，观察设置应用能否出现在虚拟显示器上，再停止。
4. 点击 B1，再点击 B2。如存在新增非零 ID，选择该 ID 执行 B3，在实时画面观察显示内容。
5. 停止 B3 的视频会话后，**务必点击恢复原始副屏配置**。
6. 下载诊断 JSON，并人工记录是否出现华为原生桌面；新增 Display ID 不等于原生电脑模式已启动。

## 安全说明

- B1 备份记录独立持久化；容器重建时请保留与 SQLite 数据库相同的数据卷，否则无法使用自动恢复。
- 存在待恢复记录时，拒绝编辑、删除、切换该设备线路或更换临时地址；请先恢复后操作。
- 实验室不会执行 `adb connect`，不自动重连，也不提供自由输入 ADB 命令功能。
- 模拟副屏可能改变手机显示状态。如果 ADB 离线，请在手机端手动恢复连接或开发者选项中的模拟显示设置。
- 如果 `dumpsys` 输出格式与解析器预期不一致，可从实验室展开原始输出，以便继续适配 Mate 30。
- 原有最多四路直播限制、会话所有权、WebSocket 鉴权和 MSE 视频链路保持不变。

自动化覆盖仅为 mock ADB 与现有项目 CI；华为 Mate 30 的 A/B 实机效果仍需用户验证。

## M2 实时画面扩展 · 屏幕电源与手动重连

设备列表每台设备单独增加「投屏时关闭手机物理屏幕」复选框，默认关闭，和画质、低延迟一样保存在本页设备选择状态中；仅在**下一轮主屏实时画面**启动时固定生效，不向实验副屏传入该选项，不修改设备数据库或其它设备状态。

- 正常启动主屏时，scrcpy-server 生成媒体初始化段后，经当前视频会话的 control socket 发送 v5.0.1 类型 10、值 0 的物理显示电源关闭指令；编码与浏览器视频通道继续运行。该指令被写入 socket 不等于 OEM 一定执行成功，需实机验证。
- 悬浮菜单上方增加「唤醒手机屏幕」：无需先启用远控。即使画面尚在启动中，收到会话 ID 后也能点击；服务端仅通过当前会话固定的 ADB 串号执行 Android `KEYCODE_WAKEUP (224)`。若 scrcpy 控制通道已经建立，还会先发 v5.0.1 类型 10、值 1 的显示电源开启指令。唤醒会取消尚未执行的本轮延迟息屏；不会通过 Power(26) 键误关已亮屏的设备。不会解锁锁屏或绕过手机认证。
- 悬浮菜单上方增加「重连此路实时画面」：**用户点击后只执行一次**。向旧 WS 发送 stop，等服务端明确返回 `ended + cleanup_complete=true`、原卡片完全销毁后，才为同一台设备的同一选择串号重新创建原画质、原显示源及原息屏选项的单独视频会话。其它设备保持原状；旧会话未完整清理、ADB 串号变化、连接不可用时不重启，不自动调用 `adb connect`，不后台重试。
- 竖屏悬浮菜单向上依次排列日志、唤醒、重连；横屏对上方操作采用横向展开，避免窄高比例画面被裁掉。原有下方返回/主页/最近任务及远控启用机制不变。

验证要求：主屏初始已休眠时仍能从收到 `starting` 事件起点击唤醒，不依赖接收到第一帧；多设备息屏选项互不串扰；重连必须等待旧服务端清理确认；异常/不完整清理不进行自动重连。实际手机息屏是否持续保留编码画面需对应 OEM 实机验证。


## 华为原生电脑模式专项 B 组（2026-10-20）

此功能基于最新的 `feat/m3-openwrt-discovery` 修改。原有 A1/A2 不变；原 B1/B2/B3 在页面标记为 O1/O2/O3，内部 API 保持兼容。**本组是技术假设实验，不承诺能越过华为签名权限或完成真正 Cast+ 协议握手。**

- **B1**：独立测试 APK 的前台服务请求 Android 创建 `CastPlusDisplay`，1920×1080/240，使用 PUBLIC|PRESENTATION|OWN_CONTENT_ONLY 标志；通过 ADB `install -r` 和显式 `am start-foreground-service` 启动。以 `dumpsys display` 实际返回的名称、Type 5、Display ID 检验，不根据启动命令成功就判定 PC Mode 成功。
- **B2**：持久化备份原始 `settings secure selected-proj-mode`，显式写入 1，停止/重启**仅本测试服务**，使 DisplayAdded 流程重新发生。若检测到设置被其他操作改动，则拒绝覆盖。
- **B3**：仅 B1 已验出 Type 5 `CastPlusDisplay` 且 `hw.pc.cast.mode` 未激活时，尝试 `com.android.server.pc.action.SWITCH_MODE` 广播；收集权限拒绝，不声明广播完成等于模式启动。
- **B4**：读取 `hw.pc.cast.mode`、真实显示屏和桌面 SystemUI/Explorer 服务线索。即使出现系统证据也要使用 O3 选择 Display ID 预览，人工确认华为任务栏、桌面和独立窗口，横屏设置页不能算成功。
- **恢复**：B1 创建前落盘备份设备串号与原始桌面偏好；独立恢复入口只停止本实验服务和恢复经校验的原始偏好。不删除其他用户的无线投屏会话，不卸载其他软件。恢复失败保留 `*.display-lab.json.castplus`。设备删除/切线受待恢复状态保护；恢复前必须停止此设备的实验直播。

### 构建与部署辅助 APK（按需）

GitHub Actions → `Build opt-in CastPlus experiment helper` → 手动运行工作流，下载构建产物 `easyadb-castplus-lab-apk` 内的 `app-debug.apk`，重命名为 `castplus-lab.apk`，放入 EasyADB NAS 项目目录 `./data/storage/castplus-lab.apk`。该目录在容器中已有挂载路径 `/app/data`，因此无需更改现有 Compose、Dockerfile 或官方固定版本 scrcpy-server。请仅使用当前可信仓库分支生成的 APK。

辅助组件源码在 `castplus-helper/`，权限声明限制普通第三方应用唤起该测试服务，使用的是 ADB Shell 已有的 `android.permission.DUMP`。Android 或华为固件仍可能拒绝服务启动、PUBLIC 虚拟屏、输入/捕获或桌面接管；请保留并导出相应错误，不依赖 ROOT、系统签名修改、预装替换或假冒华为 Cast+ 包。

所有步骤由用户手动触发，无后台重试和自动连接；B1/B2/B3、恢复动作与本设备已有直播会话互斥。自动化测试仅覆盖 mock ADB、程序行为和 CI，不能替代 Mate30 实机验收。
